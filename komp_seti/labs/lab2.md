##  ЧАСТЬ 1: Подключение к Raspberry Pi по SSH

### Шаг 1: Подключение к устройству

```bash
ssh user@192.168.129.150
```

> При первом подключении система запросит подтверждение подлинности хоста — введите `yes`.

### Шаг 2: Ввод пароля

```
Пароль: 123
```

>  Символы пароля не отображаются при вводе — это нормальное поведение.

### Шаг 3: Работа в корневом каталоге

После успешного входа вы получите доступ к консоли Raspberry Pi.

```bash
# Просмотр корневого каталога
cd /
ls

# Перейдите в каталог с номером вашей группы и создайте папку с фамилией
# Пример для группы 123 и фамилии Иванов:
mkdir /123/ivanov

# Выполните задание по созданию каталогов и файлов
cd /123/ivanov
mkdir task1 task2 task3
touch task1/file1.txt task2/file2.txt task3/file3.txt
echo "Hello Raspberry" > task1/hello.txt
```

### Шаг 4: Проверка структуры каталогов

```bash
ls -R /123/ivanov
```

>  **Сделайте скриншот** с результатом выполнения команды `ls -R` для отчёта.

[результат выполнения команды](images/1.png)

### Шаг 5: Завершение сеанса

```bash
exit
```

##  ЧАСТЬ 2: Настройка аутентификации по SSH-ключам

### Зачем нужны SSH-ключи?
-  Не нужно вводить пароль при каждом подключении
-  Повышенная безопасность (при использовании парольной фразы)
-  Удобство автоматизации и скриптов

### Шаг 1: Проверка наличия существующих ключей (на ПК)

```bash
ls ~/.ssh
```

Если найдены файлы `id_rsa.pub` или `id_dsa.pub` — ключи уже существуют, генерацию можно пропустить.

### Шаг 2: Генерация SSH-ключей

```bash
ssh-keygen
```

```
Generating public/private rsa key pair.
Enter file in which to save the key (/home/user/.ssh/id_rsa): [Enter]
Enter passphrase (empty for no passphrase): [Enter или введите пароль]
Enter same passphrase again: [Повторите пароль]
```

>  Рекомендуется оставить поле пароля пустым для учебных целей.

### Шаг 3: Проверка созданных ключей

```bash
ls ~/.ssh
```

Результат:
| Файл | Описание |
|------|----------|
| `id_rsa` |  Приватный ключ (хранится на ПК, не передавать!) |
| `id_rsa.pub` |  Публичный ключ (копируется на Raspberry Pi) |

[Проверка созданных ключей](images/2.png)

### Шаг 4: Копирование публичного ключа на Raspberry Pi

```bash
ssh-copy-id user@192.168.129.150
```

> Введите пароль при запросе — ключ будет добавлен в `~/.ssh/authorized_keys` на устройстве.

#### Альтернативный способ (вручную):

```bash
# Копирование содержимого публичного ключа
cat ~/.ssh/id_rsa.pub

# На Raspberry Pi:
mkdir -p ~/.ssh
nano ~/.ssh/authorized_keys
# Вставьте содержимое id_rsa.pub, сохраните и выйдите
chmod 600 ~/.ssh/authorized_keys
chmod 700 ~/.ssh
```

### Шаг 5: Проверка подключения без пароля

```bash
ssh user@192.168.129.150
```

>  Если настройка выполнена верно — вход произойдёт без запроса пароля.

##  Контрольные вопросы

### 1. Что такое командная строка?

**Командная строка** (терминал, консоль, shell) — это текстовый интерфейс для взаимодействия пользователя с операционной системой. Она позволяет:
- Вводить команды для выполнения операций с файлами, процессами, сетью
- Автоматизировать задачи с помощью скриптов
- Получать доступ к низкоуровневым функциям ОС

Команды обрабатываются **интерпретатором** (bash, zsh, cmd, PowerShell), который передаёт их ядру системы.

---

### 2. Основные команды управления файлами

#### Linux/Unix:
```bash
ls              # Список файлов
cd <path>       # Смена каталога
pwd             # Показать текущий путь
mkdir <name>    # Создать каталог
rmdir <name>    # Удалить пустой каталог
touch <file>    # Создать файл
cp <src> <dst>  # Копировать
mv <src> <dst>  # Переместить/переименовать
rm <file>       # Удалить файл
rm -r <dir>     # Удалить каталог рекурсивно
chmod           # Изменить права доступа
chown           # Изменить владельца
```

#### Windows (CMD):
```cmd
dir             # Список файлов
cd <path>       # Смена каталога
mkdir / md      # Создать каталог
rmdir / rd      # Удалить каталог
copy            # Копировать
move            # Переместить
del / erase     # Удалить файл
ren             # Переименовать
type            # Просмотреть файл
```

### 3. Команды вывода информации о системе

#### Linux:
```bash
uname -a        # Информация о ядре
hostname        # Имя хоста
whoami          # Текущий пользователь
id              # UID/GID пользователя

ps aux          # Список процессов

lsblk           # Блочные устройства
```

#### Windows:
```cmd
systeminfo      # Полная информация о системе
hostname        # Имя компьютера
whoami          # Текущий пользователь
date / time     # Дата и время
tasklist        # Список процессов
taskmgr         # Диспетчер задач
```

### 4. Команды ввода/вывода файлов

```bash
# Просмотр
cat <file>          # Вывод содержимого (Linux)
type <file>         # Вывод содержимого (Windows)
less / more         # Постраничный просмотр
head -n 10 <file>   # Первые 10 строк
tail -n 10 <file>   # Последние 10 строк

# Редактирование
nano / vim / vi     # Редакторы в Linux
notepad             # Блокнот в Windows

# Перенаправление
command > file      # Запись в файл (перезапись)
command >> file     # Добавление в конец файла
command < file      # Чтение из файла
cmd1 | cmd2         # Конвейер: вывод cmd1 → ввод cmd2

# Поиск
grep "текст" file   # Поиск в Linux
findstr "текст" file # Поиск в Windows
```

### 5. Возможно ли полноценное управление системой только через командную строку?

**Да, возможно и часто предпочтительно.**

#### Аргументы «за»:
 Полный доступ ко всем функциям ОС  
 Автоматизация через скрипты (bash, PowerShell)  
 Удалённое администрирование (SSH, telnet)  
 Минимальное потребление ресурсов  
 Воспроизводимость и документирование команд  
 Работа на headless-серверах без графического интерфейса  

#### Ограничения:
 Некоторые приложения требуют GUI  
 Высокий порог входа для новичков  
 Отсутствие визуальной обратной связи  

> **Вывод**: Для системного администрирования, DevOps и серверных задач CLI — основной и наиболее эффективный инструмент.

### 6. Отличия командной строки Windows от MS-DOS

| Критерий | MS-DOS | Windows CMD / PowerShell |
|----------|--------|-------------------------|
| **Архитектура** | Однозадачная ОС | Подсистема в многозадачной ОС |
| **Доступ к железу** | Прямой | Через Win32 API |
| **Файловая система** | FAT12/16, 8.3 | NTFS/FAT32, длинные имена, Unicode |
| **Команды** | В COMMAND.COM | Внешние утилиты + встроенные |
| **Скриптинг** | .BAT (ограниченный) | .BAT/.CMD, PowerShell (ООП, объекты) |
| **Безопасность** | Нет разграничения прав | UAC, права доступа, аудита |
| **Сеть** | Минимальная | Полная интеграция с протоколами |
| **Интерфейс** | Текстовый 80×25 | Консоль с буфером, цветом, мышью |

>  PowerShell использует **объектную модель**, а не текстовые потоки — это фундаментальное отличие от DOS.

### 7. Примеры интерпретаторов команд в других ОС

| ОС | Интерпретатор(ы) | Особенности |
|----|-----------------|-------------|
| **Linux** | `bash`, `zsh`, `fish`, `sh` | POSIX, скриптование, автодополнение |
| **macOS** | `zsh` (по умолчанию), `bash` | Unix-основа, BSD-утилиты |
| **FreeBSD** | `tcsh`, `csh`, `sh` | Безопасность, стабильность |
| **Android** | `mksh`, `toybox` | Упрощённые утилиты для мобильных |
| **PowerShell** | `pwsh` (кроссплатформенный) | Объектно-ориентированный, .NET |
| **Plan 9** | `rc` | Минимализм, влияние на современные shell |
| **IBM AIX** | `ksh`, `bash` | Корпоративные функции |

#### Популярные shell в Unix-подобных системах:
- **bash** — стандарт де-факто, богатая документация
- **zsh** — расширенное автодополнение, темы (Oh My Zsh)
- **fish** — дружественный интерфейс, подсветка «из коробки»
- **sh** — минимальный, для совместимости скриптов
